# 逆向记录：小米移动电源 WebHID 详情页

本文记录 [`powerbank.mieco.net`](https://powerbank.mieco.net/) 的公开前端行为分析，以及本项目如何用 Vue 3 重新实现同一套设备读取流程。目标是互操作和本地数据展示，不包含原始 React 代码或图片素材。

> 非官方项目，与小米公司无隶属关系。请自行承担连接设备、读取数据的风险。

## 1. 目标与范围

原始页面是一个 React 单页应用，通过 **WebHID** 直接读取连接到电脑的小米移动电源。设备数据不经过服务器，页面只负责：

1. 请求用户授权 HID 设备；
2. 发送握手帧；
3. 按需读取电池、电芯、电芯编码和异常记录；
4. 解析 32 字节报告并渲染界面。

本项目重新实现了：

- WebHID 设备选择、打开、关闭与断开监听；
- 帧构造、CRC-8、输入报告切分；
- 所有公开读取命令及响应解码；
- 15 秒心跳、断线提示、授权超时处理；
- 原始页面中的型号、文案和型号特定规则；
- 额外提供演示模式、协议日志和更完整的移动端布局。

未实现/未暴露：

- Qi2.2 开关（社区 Python 工具中有 `0x06/0x07` 命令，原始网页没有把它做成 UI；本项目仅对 `WPB1025S` / `WPB1026S` 提供开关）；
- 固件升级、参数写入、任意原始命令发送。

## 2. 原始站点观察

### 2.1 静态资源

页面本身是静态 HTML，脚本与样式托管在小米 CDN：

| 资源                               | 说明                                    |

- `/exception-guide`：常见异常处理

### 2.2 浏览器限制

原页面在移动端或非 Chromium 桌面浏览器上会显示“当前浏览器暂不支持连接设备”。它还：

- 排除 Android/iOS 与窄屏触控设备；
- 排除 Brave（`'brave' in navigator`）；
- 在检测到 DevTools 时断开设备；
- 覆盖 `navigator.hid.getDevices`，避免直接枚举已授权设备。

本项目保留“桌面 Chromium + HTTPS”这一必要条件，但不做 DevTools 检测，也不禁用 `getDevices`，以保持可调试性和透明度。

## 3. HID 会话

### 3.1 设备过滤

```ts
navigator.hid.requestDevice({
  filters: [{ vendorId: 0x2717 }, { vendorId: 0x1a86 }],
})
```

- `0x2717`：Xiaomi
- `0x1a86`：常见 USB-HID 桥接芯片
- 产品名通常为 `XiaomiPowerBank`
- 输出报告：`device.sendReport(0, frame)`
- 输入报告：监听 `inputreport`，`event.data` 为报告内容（不含 reportId）

### 3.2 报告大小

每个报告固定 **32 字节**。不足 32 字节的帧在尾部补 `0x00`。

### 3.3 通用帧格式

| 偏移         | 字段    | 说明                    |
| ------------ | ------- | ----------------------- |
| 0            | HEAD    | 固定 `0xA5`             |
| 1            | CMD     | 命令字                  |
| 2            | LEN     | payload 长度            |
| 3 .. 3+LEN-1 | PAYLOAD | 数据                    |
| 3+LEN        | CRC8    | 对 `HEAD..PAYLOAD` 计算 |
| 其余         | 0x00    | 填充到 32 字节          |

CRC 参数：

- 名称：CRC-8/ATM（与源码中的 `calculateCRC8` 一致）
- 多项式：`0x07`
- 初值：`0x00`
- 输入/输出反射：无
- 结果异或：`0x00`

校验向量：

```text
A5 06 01 00  ->  CRC = D9
```

> 注意：部分社区文档中的示例写作 `...C8`，与网页源码的算法结果不一致。本项目以网页源码中的逐位算法为准，并在测试中固定了 `D9` 这个向量。

### 3.4 Hello / 心跳帧

Hello 帧不是通用帧格式，而是固定布局：

| 偏移 | 长度 | 字段                           |
| ---- | ---- | ------------------------------ |
| 0    | 1    | `0xA5`                         |
| 1    | 1    | `0x00`（Hello）                |
| 2    | 1    | `0x0D`（13）                   |
| 3    | 4    | 时间戳：Unix 秒 + 8 小时，小端 |
| 7    | 9    | ASCII `xiaomi-pb`              |
| 16   | 1    | 对偏移 0..15 计算 CRC8         |
| 17   | 15   | 补零                           |

连接成功后每 15 秒重发一次 Hello 作为心跳；设备返回 `0x10`。原页面使用 Web Worker 定时，避免后台标签页被节流；本项目同样使用 Web Worker，并在不支持 Worker 时回退到 `setInterval`。

## 4. 命令与响应

| 发送 CMD | 响应 CMD | 名称                   | 请求 payload             |
| -------- | -------- | ---------------------- | ------------------------ |
| `0x00`   | `0x10`   | Hello                  | 特殊帧                   |
| `0x01`   | `0x11`   | 电池信息               | 空                       |
| `0x02`   | `0x12`   | 电芯状态               | `[start, end]`           |
| `0x03`   | `0x13`   | 异常记录               | `[start LE16, end LE16]` |
| `0x04`   | `0x14`   | 电芯编码               | `[cellIndex]`            |
| `0x05`   | —        | 断开连接               | 空                       |
| `0x08`   | `0x18`   | 温度阈值与型号         | 空                       |
| `0x0A`   | —        | 心跳（复用 Hello 帧）  | —                        |
| `0x06`   | `0x16`   | Qi2.2 使能（社区扩展） | `[0/1]`                  |
| `0x07`   | `0x17`   | Qi2.2 状态（社区扩展） | 空                       |

`0x06` / `0x07` 仅在 `WPB1025S` / `WPB1026S`（小米金沙江充电宝 超薄磁吸 10000 45W）上启用；社区反馈 `WPB0525S` 开启失败。`0x17` 的 payload 至少 2 字节：`[status, enabled]`，`status == 0` 表示查询成功，`enabled == 1` 表示已开启。`0x16` 的 payload 至少 1 字节，`status == 0` 表示设置成功。写入请放在明确的二次确认之后。

`0x02` 的 `start` / `end` 是 1-based 电芯编号。原页面请求 `[1, cellCount]`。

`0x03` 的起止编号是 16 位小端，原页面每批最多 7 条，逐批请求。

## 5. 响应解码

### 5.1 `0x10` Hello 响应

| 偏移 | 长度 | 字段                               |
| ---- | ---- | ---------------------------------- |
| 0    | 2    | 型号 ID，LE16                      |
| 2    | 20   | SN，ASCII，补零                    |
| 22   | 1    | 充电状态：0 空闲 / 1 充电 / 2 放电 |

至少需要 23 字节。型号 ID 通过型号表映射到产品名和型号代码。

### 5.2 `0x11` 电池信息

至少 18 字节。

| 偏移 | 长度 | 字段                                           |
| ---- | ---- | ---------------------------------------------- |
| 0    | 1    | 状态：0 成功                                   |
| 1    | 1    | 激活状态：0 未激活 / 1 已激活                  |
| 2    | 2    | 循环次数，LE16                                 |
| 4    | 2    | 健康度（%），LE16                              |
| 6    | 1    | 状态字节：bit7..6 充放电状态，bit5..0 故障类型 |
| 7    | 2    | 当前故障值，LE16                               |
| 9    | 2    | 历史异常条数，LE16                             |
| 11   | 1    | 串并联配置：高 4 位串数，低 4 位并数           |
| 12   | 1    | 当前电量 %                                     |
| 13   | 1    | 温度，有符号 int8                              |
| 14   | 2    | 电池串总电压，LE16，mV                         |
| 16   | 2    | 电流，有符号 int16，mA                         |

状态字节的 bit7..6：

- `0`：放电
- `1`：充电
- `2`：空闲

电芯数量：

```text
series  = (config >> 4) & 0x0F
parallel = config & 0x0F
cellCount = (series  == 0 && config != 0 ? 1 : series)
          * (parallel == 0 && config != 0 ? 1 : parallel)
```

### 5.3 `0x12` 电芯状态

payload 首字节为状态，随后每 **5 字节** 一节电芯：

| 相对偏移 | 长度 | 字段                                         |
| -------- | ---- | -------------------------------------------- |
| 0        | 1    | 温度，有符号 int8，`-127` 表示该测温点不存在 |
| 1        | 2    | 电压，LE16，mV                               |
| 3        | 2    | 电流，有符号 int16，mA                       |

### 5.4 `0x13` 异常记录

payload 首字节为状态，随后最多 7 条记录，每条 **8 字节**：

| 相对偏移 | 长度 | 字段                                   |
| -------- | ---- | -------------------------------------- |
| 0        | 4    | 时间戳，LE32（设备本地北京时间墙钟秒） |
| 4        | 1    | 电芯编号                               |
| 5        | 1    | bit7..6 充放电状态，bit5..0 异常类型   |
| 6        | 2    | 数值，LE16                             |

异常类型与数值单位：

| errorType | 含义                     | 数值   |
| --------- | ------------------------ | ------ |
| 1         | 电芯过压                 | mV     |
| 2         | 电芯欠压                 | mV     |
| 3         | 高温（按充放电状态细分） | °C     |
| 4         | 低温（按充放电状态细分） | °C     |
| 5         | 过流                     | mA     |
| 6         | 短路                     | 原始值 |
| 7         | 电芯压差                 | mV     |
| 8         | MOS 异常                 | 原始值 |
| 9         | AFE 异常                 | 原始值 |

充放电状态位：

- `0x00`：放电
- `0x40`：充电
- `0x80`：空闲

原页面对 `WPB1007ZX` 有一个特殊过滤：时间戳早于 `1772323200`（2026-03-01）的记录不显示。本项目保留该规则。

时间戳展示：设备写入的是北京时间墙钟值。本项目用 UTC 格式化原始秒数，从而在任何浏览器时区下都显示相同的“设备时间”。

### 5.5 `0x14` 电芯编码

| 偏移    | 长度 | 字段                       |
| ------- | ---- | -------------------------- |
| 0       | 1    | 状态：0 成功               |
| 1       | 1    | 电芯编号                   |
| 2 .. 30 | ≤29  | ASCII 编码，遇 `0x00` 截断 |

编码格式（前 9 位固定）：

```text
ATLN D A G 3 F -1D9A26A0123
^^^^ ^ ^ ^ ^ ^
|    | | | | └─ 日编码（F=15）
|    | | | └─── 月编码（3=3 月）
|    | | └───── 年编码（G=2026）
|    | └─────── 电池类型编码
|    └───────── 产品类型编码
└────────────── 厂商代码（4 位）
```

可变部分：

- 可选 `-R-` / `R-` 前缀：阶梯/返修标识；
- 分隔符；
- 校验码；
- 3 位小米项目码；
- 其余可变数据。

`compositeKey = 厂商代码 + 小米项目码`，例如 `ATLND9A` 对应 `WPB0525S/WPB1025S`、电芯型号 `436678B`。完整映射位于：

- `src/data/batteryIdMaps.ts`
- `src/lib/protocol/battery-id.ts`

### 5.6 `0x18` 温度阈值与型号

| 偏移 | 长度 | 字段                       |
| ---- | ---- | -------------------------- |
| 0    | 1    | 状态：0 成功               |
| 1    | 2    | 高温阈值，有符号 int16，°C |
| 3    | 2    | 低温阈值，有符号 int16，°C |
| 5 .. | 剩余 | 电池型号 ASCII             |

原页面只对型号 ID > 14 的设备请求该命令；本项目沿用该规则（演示模式除外）。

## 6. 会话流程

```text
用户点击连接
  -> navigator.hid.requestDevice
  -> device.open()
  -> 监听 inputreport / disconnect
  -> 发送 Hello（1.5 s 超时）
  -> 失败：显示“设备未授权”并关闭
  -> 成功：解析型号、SN、充电状态
  -> 请求 0x11 电池信息（最多 2 次，指数退避）
  -> 请求 0x12 电芯状态
  -> 请求 0x18 温度阈值（型号 ID > 14 或演示模式）
  -> 对每个电芯请求 0x14 编码（最多 2 次）
  -> 启动 15 s Hello 心跳
  -> 用户打开“异常记录”时按批请求 0x13
```

原页面的重试参数：

- 电池信息：最多 3 次，超时 1 s，退避 0.5 s / 1 s
- 电芯状态：最多 3 次，超时 8 s
- 电芯编码：最多 3 次，超时 5 s
- 历史记录：最多 3 次，超时 2 s，批次间隔 200 ms

本项目使用更保守的 2 次重试与较短超时，避免界面长时间无响应；底层命令和响应格式保持一致。

## 7. 型号特定行为

- `WPB1007ZX`：不显示设备 SN 和电芯编码列；温度只显示第一个测温点；过滤 2026-03-01 之前的历史记录。
- `WPB1025S` / `WPB1026S`：提供 Qi2.2 状态查询与开关。状态查询失败时不显示开关；写入成功后重新查询状态确认。
- `WPB0525S`：社区反馈 `0x06` 开启失败，本项目不显示开关。
- 型号 ID > 14：额外请求 `0x18`，用返回的温度阈值替换型号表里的默认范围。
- 部分旧型号/固件不返回电芯编码；界面保留 `--`，不阻塞其他数据。
- 温度值 `-127` 表示该测温点不存在，不显示。

## 8. 与类似开源项目的关系

### [yomiel-s/xiaomi-powerbank-tools](https://github.com/yomiel-s/xiaomi-powerbank-tools)

MIT 许可的 Python HID 工具，提供了非常有价值的协议整理：

- 确认了 VID/PID、帧格式、CRC、Hello 布局；
- 补充了 Qi2.2 命令 `0x06/0x07`；
- 演示了 Python 端的 `hidapi` 实现。

本项目未复制其 Python 代码；协议常量与解码逻辑在 TypeScript 中独立重写，并加入了原网页中的历史记录、电芯编码、型号表等逻辑。

### [xingrz/ChargeMon](https://github.com/xingrz/ChargeMon)

基于 HTML5 的 USB 电表上位机（GPL-3.0）。它帮助确认了 Web 端串口/HID 仪表类界面的交互模式。本项目未复用其代码或样式。

### [Smart-financial-class/PowerMonitor](https://github.com/Smart-financial-class/PowerMonitor)

Vue 3 + Vite 的电量监控后台（MIT）。作为 Vue 3 仪表盘的结构参考；本项目未复用其代码。

### [WICG/webhid](https://github.com/WICG/webhid)

WebHID 规范与示例，用于确认 `requestDevice`、`sendReport`、`inputreport` 和 `disconnect` 的行为。

## 9. 测试与验证

由于开发环境没有实体移动电源，本项目通过 `MockTransport` 模拟设备：

- 完整握手；
- 电池信息；
- 两节电芯状态；
- 两条电芯编码；
- 温度阈值；
- Qi2.2 状态查询与开关；
- 三条历史记录；
- 心跳与断开。

单元测试位于 `src/tests/`，运行：

```bash
npm test
```

测试覆盖 CRC、帧切分、各响应解码器和完整会话流程。真实设备/固件仍可能存在差异，尤其是：

- 历史记录条数与批次边界；
- 某些型号不返回电芯编码；
- 不同固件的温度阈值命令支持情况；
- Qi2.2 命令只在 `WPB1025S` / `WPB1026S` 上验证，其他型号可能超时或不响应；
- USB 线缆是否支持数据传输。

## 10. 已知限制

- 没有实体设备时的验证仅限于模拟数据；
- WebHID 只在桌面 Chromium 且安全上下文下可用；
- 设备时间戳按北京时间墙钟处理；
- 除 `WPB1025S` / `WPB1026S` 的 Qi2.2 开关外，不提供其他写入类操作；开关需要二次确认，状态查询失败时不显示；
- 原始站点可能随时更新，协议/型号表可能变化。
